Implemented locally 2026-10-12. The Person page now offers an on-demand memory/evidence inspector. Its owner-session GET API is `/api/person/{id}/observations`, with an optional UUID `cursor`. The API validates authorization before IDs/queries, returns private no-store responses, and uses the app's `DATABASE_URL` pool. Capture credentials do not authorize it. No schema migration, backfill, real review, Vercel deployment, or retained database change occurred.

The reader uses a checked repeatable-read read-only transaction. It loads 20 stored observations per page, with a 21st row determining the next UUID cursor. Pages use stable UUID order rather than claiming chronological ranking. Historical/archived observations remain visible. Missing/aliased Person references are unavailable instead of silently resolving identity. Source and review support are bounded to 2,000 records per page; exceeding the bound fails rather than truncating provenance. The shared review graph retains its 50,000-node/edge limits.

Activity follows the exact graph query used by review transactions, including archives, aliases, explicit reviews, revisions and obsolete capture-field heads. Inactivity propagates through supporting dependencies across subjects, while independent User authorship is retained. This shared query was exported without changing the writer's locking/invalidation protocol. Historical observations display as history and receive no current generic review controls. The server remains authoritative if an inspection becomes stale before a mutation.

The inspector preserves original words, truth layer, semantic role, stored support status, recorded timestamp, revisions and prior decisions. It does not treat support status or an existing legacy profile projection as new verified fact. Source excerpts are checked against their matching stored representation with Unicode code-point offsets; location verification establishes exact excerpt integrity, not semantic entailment or external truth. Unsafe source URLs are removed. Full representation text is not sent to the client. Direct evidence includes original source/capture references and supporting-observation identifiers; recursively browsing all referenced observations is not implemented by this slice.

Explicit generic controls are confirm, correct, reject and archive. Confirmation requires suitable stored non-User text and records those exact words as a User assertion; correction accepts the user's revised text. User text cannot be generically rejected, but can be revised or archived. Identity proofs are marked for separate identity review and have no generic controls. Each action requires a second explicit submit gesture; there is no automatic review or queue obligation. The pending request ID/payload is retained for retries while the control remains mounted. Correction text is frozen after submission until cancellation, avoiding changed retries. Receipt/revision rules still protect server-side replay and stale operations. Cancel/navigation after a network failure does not establish whether a submitted decision committed; inspect refreshed history before making another decision.

The inspector refreshes its current page after success and reports inspection/review failures without fabricating data. No observations means no observation history is available on that page; existing legacy captures have not been backfilled or silently upgraded. Identity review gestures, Person archival controls, full revision navigation, and replacing the rest of the legacy profile presentation remain separate work. This is the first inspection surface, not complete Person-page migration.

An existing privacy gap was fixed: Person metadata now calls the owner session requirement before fetching a private name. Unauthenticated page requests no longer perform the prior name lookup outside the page guard.

Focused Neon validation via `node scripts/database/validate.mjs --inspection-only` passed 15 checks. Public aggregate counts were unchanged after rollback. Fixtures do not bypass the read-only check in the application wrapper; the shared query body is exercised inside their enclosing write transaction.

The built app passed 11 HTTP assertions for private authorization denial with missing/legacy/malformed cookies and an unauthenticated Person-page redirect. No private Person, valid token, password, or real review was requested; the loopback server was stopped. Authenticated interactive browser behavior, keyboard/mobile review interaction, and deployment remain unverified. The separate earlier SQL review/session/export/throttle baselines remain historical evidence, not a new complete SQL-suite run. Restoration remains explicitly deferred.

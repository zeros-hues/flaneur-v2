# Person archival and legacy reader compatibility

Note authoring update, 2026-10-12: live note saves now append immutable User observations, and revisions use the correction service. Legacy in-place PATCH is retired; earlier notes remain preserved/read-only pending reviewed backfill. The legacy supplied note store described below remains only in rollback compatibility fixtures. See [immutable notes](IMMUTABLE_NOTES.md).

Implemented locally 2026-10-12. The Person page now offers a separate two-step archive gesture through owner-write `POST /api/review`. Pending request IDs remain stable for retries; errors do not claim success. Archived pages remain inspectable at their canonical IDs and show the archive timestamp/history notice. Legacy notes become read-only and nearby recommendations are omitted on these historical pages. No restore/delete operation is exposed. No real Person was archived, migration/backfill run, Vercel deployment changed or restoration test performed.

The supplied archive service preserves Person, original captures, notes, observations, supports, reviews and source identity links. It records the registry archive marker/receipt, withdraws active endpoint relationships, invalidates dependent generated work and fences parse/object jobs atomically. Conflicting/stale retries remain server-validated. Existing v2 inspectors already show retained history while disabling active controls for archived Persons.

Legacy readers previously ignored the registry archive marker. A shared SQL eligibility module now requires active canonical registry membership before structural/semantic search ranking and limits, answer retrieval, City placement/pairs, search coverage, Concept artifact/Person lists, query margins, nearby Persons, and legacy Walk selection/drafting. Legacy person-authored Artifact projections are excluded from active reader paths when their author Person is archived or aliased. Independent Artifacts remain eligible unless their own registry is inactive. Source rows are not deleted or permanently reassigned. V2 multi-author relationship semantics remain separate from these compatibility projections.

Old co-occurrence edges may be shown only if an eligible Artifact currently supports the pair. Stored aggregate counts/rank weights are retained; this slice does not recompute historical `raw_count`/document-frequency values or complete the graph migration. The old SM-2 Walk algorithm remains a migration gap; eligibility filtering does not make its scheduling behavior satisfy the new PRD. Legacy capture/parser/enrichment writers also remain to be migrated; they may retain/update archived compatibility projections, but registry archival is not cleared by this work and active readers exclude the Person. Authoritative v2 derived-state handling remains in the archive service.

Note create/update and legacy Walk actions now acquire a share lock on the canonical active Person registry row before writing. This serializes those operations against Person archival's update lock; stale/archived/aliased Person writes fail. Existing source/User note bodies remain intact. Legacy active note editing/validation still follows the earlier implementation (including in-place edits and trimming); immutable v2 note authoring is separate remaining work, not justified merely by retaining this compatibility handler. The supplied note store allows synthetic SQL tests without loading app credentials. Full cross-connection lock-race tests were not added; row-lock protocol and sequential behavior were inspected/exercised.

Validation exposed a runtime integration defect: Drizzle changes the pool's timestamp parsers and JSON serializers. Direct PostgreSQL stores sharing that pool could fail session expiry formatting or structured identity writes. `lib/db.ts` now maintains separate ORM and direct-store pools, both using runtime `DATABASE_URL`; each is configured for at most five connections. Direct SQL codecs are protected from Drizzle mutation. Both pools are cached for development hot reload. Restart the server to replace prior pool/runtime state; a reused pre-change development pool may still carry its old connection maximum until restart. `DIRECT_URL` remains for administrative tools only. No database was created by allocating application connection pools.

Direct session/archive/worker timestamp conversion also now accepts validated zoned strings and native Date values through a shared private-error helper. Two new synthetic tests cover equivalent timezone instants and invalid/ambiguous values. SQL fixture construction isolates Drizzle codec mutation; bounded stable error-code reporting can inspect wrapped driver causes without printing messages, queries, parameters or credentials. An initial fixture enum typo and old Date-only fixture assertion were corrected before the final successful run.

All 228 synthetic tests, TypeScript and the production build pass. Fresh `node scripts/database/validate.mjs --archive-compatibility-only` passed **119 checks** on Neon dev through `DIRECT_URL`. It includes actual session fixtures; shared SQL eligibility/note-store queries; Person archival/replay; retained User/source text; suppressed authored Artifacts/co-occurrences; independent Artifact support; alias/missing-person write denial; existing observation/Person archive dependency fixtures; and actual worker claim/renew/reclaim/completion checks. The worker fixture required an idle queue and held a short table lock to prevent real jobs being selected. Every fixture rolled back, existing auth state was preserved by session validation, public aggregate counts were unchanged, and no real Person was archived. These are focused compatibility checks, not a new full SQL-suite claim.

The built app passed 12 HTTP assertions for unauthorized archive/note/Walk attempts and protected Person/Concept redirects. No password/token/private records were submitted; no real notes were written. The loopback test server was stopped. Concept metadata now also checks the owner session before reading a private label, matching the prior Person metadata fix. The 12 HTTP assertions were rerun successfully against the final build after pool separation; successful pool/codec behavior is covered by the focused SQL run. Interactive browser archival and deployment remain unverified. Restoration verification stays deferred.

Prepared 2026-10-12. `ownerSessionRuntime` composes the private-password provider, shared throttle, session HTTP handler, and owner authorization. `postgresOwnerSessionRuntime` supplies both actual PostgreSQL stores from one caller-owned pool. Neither module loads environment values, opens a pool, activates a route, or writes at construction time. These modules are for Node server use, not client components or Edge runtime.

Authorization checks the authenticated principal against the configured notebook owner and requested permission. It defaults to write; read is explicit. A valid session belonging to another principal is denied. Capture-secret headers/cookies cannot authorize these services. Lookup failures propagate so eventual route wrappers can return unavailable without granting access. Configuration failures expose only a stable message. Existing login/logout safeguards remain in the handler.

Configuration supplies `ownerPrincipalId`, `passwordHash`, and a trusted HTTPS `origin`; optional bounded throttle policy uses the existing 8-attempt/900-second defaults. No caller-provided host/header sets policy. Future application composition must use the normal runtime `DATABASE_URL` pool; `DIRECT_URL` remains exclusive to administrative migrations/SQL validation. No application environment singleton or production route is connected in this slice.

`npm run auth:status` privately uses the installed Next environment loader, including `.env.local`/development overrides and dollar expansion, validates credential format/origin, and prints booleans only. The loader's logger is suppressed to keep raw parse errors private. `configurationReady` describes local configuration only; it is not deployment/browser/database readiness.

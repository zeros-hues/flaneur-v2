# Person and Concept trail presentation

Implemented locally on 2026-10-17 against the updated PRD sections 8.3–8.4. This is a presentation and read-only query slice; it does not activate capture processing or migrate historical notebook content.

Person pages now lead with identity, explicitly unverified earlier profile context, the user's preserved notes, and recorded Encounters. Existing immutable-note, observation review, identity review, and Person archive controls remain connected. Earlier role/education projections and generated synthesis remain inspectable inside a collapsed, explicitly unverified section. Generated synthesis is labelled Inference and its spacing is preserved. Legacy domain/mode classifications and the old shared-tag neighbourhood are no longer presented as facts or supported relationships. The profile URL is restricted to HTTP(S) without embedded credentials. Source access leads through recorded Encounters and saved Artifacts to the existing capture/evidence inspector.

Concept pages show appearances across recorded Encounters, saved Artifacts, and directly recorded observations/evidence. A direct Encounter link is distinguished from an Encounter reached through an Artifact's legacy concept association. People and other objects are shown with their actual recorded Encounter relation; shared context does not establish authorship or a personal relationship. Legacy hashtag provenance stays distinct from inferred concept links, with both explicitly identified as legacy associations whose evidence has not been migrated. Stored concept categories are labelled as stored categories.

The old Concept document-frequency totals, concept-edge raw counts, and implied author rankings have been removed from these pages. They are not recomputed or used to imply authoritative frequencies. The unused legacy Concept reader and Person neighbourhood reader were removed. Legacy saved-answer citations with Artifact IDs now open `/artifact/[id]` instead of relying on the retired Person post-list anchors.

The new `lib/trail/postgres.ts` query body accepts supplied connections for SQL validation. Its runtime wrapper checks repeatable-read, read-only isolation and applies a 20-second statement timeout. Root IDs must have the expected canonical registry kind. Archived roots remain inspectable as history; associated Encounter/Artifact lists include only active canonical records. An Artifact remains independently visible after a legacy associated Person is archived. Aliases are excluded without guessing a new identity or copying associations.

Encounter and Artifact lists use separate pages of 20, with timestamp-plus-UUID keyset ordering, newest first. Equal timestamps retain deterministic traversal. UUID cursors are validated, and unknown or ineligible cursors return no entries for that list. Encounter context and Artifact previews are explicitly excerpts (2,000 and 300 PostgreSQL characters respectively); links open full inspection. Stored whitespace and Unicode are escaped as text. Encounter link expansion fails explicitly above 200 links instead of silently dropping associations. Concept observations reuse the existing evidence/dependency/review reader, including current versus inactive history, truth layer, semantic role, support status, supports/contradicts roles, quote integrity and original capture links. Quotation integrity is not represented as semantic verification.

Pages authenticate before validating route input or reading notebook data. Metadata uses generic titles. Malformed/ambiguous cursors are rejected; reader failures return a private unavailable message without database details.

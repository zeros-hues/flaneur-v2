Implemented locally 2026-10-12. `POST /api/review` now composes all seven prepared observation/identity/archive services over the existing runtime `DATABASE_URL` pool. The server-only runtime obtains the configured owner session policy; `DIRECT_URL` is used only by separate administrative validation. Construction is lazy and performs no mutations. No Vercel deployment or actual owner review was performed.

`ownerReviewHandler` explicitly requires write permission from the owner runtime. Read-only, missing, malformed, revoked/expired, and foreign-owner sessions cannot mutate or even reach body parsing/store transactions. Capture-secret cookies/headers are ignored. Exact configured HTTPS Origin is mandatory after authorization; non-HTTPS server origins now fail configuration. Public errors/headers retain the strict handler contract, with constant unavailable responses for configuration/storage failure and no raw logging. Caller payloads cannot choose a principal, permission, or truth layer.

All seven actions and their strict request fields are recorded in [REVIEW_HTTP.md](REVIEW_HTTP.md). Each explicit decision uses one request UUID; retries reuse the same UUID and payload. Confirmation/correction append immutable User text/reviews and retain original assertions/evidence; identity operations use their dedicated proof rules. Rejection/archival invalidates dependent generated work atomically without deleting source or authored history. Receipt/revision rules reject conflicting retries and stale/unsupported targets. The route introduces no schema migration or backfill.

The UI does not yet invoke this endpoint. Connecting explicit evidence/identity review controls requires the inspection reader and an accurate presentation of stored observations; legacy profile projections must not be promoted merely because they are displayed today. No automatic model/provider/background operation submits review. Person-page archival UI remains the old local presentation until its semantics are deliberately migrated.

Local implementation, 2026-10-13. The Walk page and owner-protected `/api/walk` now use the installed persistent session store. No deployment or interactive owner login was performed.

Navigation reads the current anchored local-day session through a checked repeatable-read read-only view. It creates no Walk or exposure event. When no session exists, an explicit Start Walk form asks for timezone and optional current context. The first timezone is fixed; later navigation and context edits resume the same stored membership. Completed sessions display an ending without a refill control.

The presentation reader resolves current canonical People/Artifacts and current observation evidence. Superseded/reviewed/archived evidence does not reappear from frozen selection metadata. Earlier selection reasons are labelled as reasons at the start and suppressed when their support is no longer represented. Exact excerpts retain truth layers and support uncertainty; People open their memory page and Artifacts use safe saved HTTP(S) source URLs. Owner IDs and full stored operational history are not sent to the page.

Unavailable objects or withdrawn evidence are omitted without replacement. Read-only GET does not claim a newly completed session: it returns `needsResume`. An explicit Resume Walk POST records system unavailable resolutions and completes the stored session when appropriate. Frozen stop IDs/positions stay intact. This prevents an empty presentation from being mistaken for committed completion and preserves history without manufacturing dismissal or exposure.

Exposure requires at least 50% of the stop header to remain in the viewport for one uninterrupted second while the document is visible. Leaving the viewport, hiding the tab, or unmounting cancels the timer. A header includes its object label and a saved-text preview. Selection/response receipt alone never counts as shown. Keyboard users can focus each stop. No surfaced Encounter is synthesized from these requests; event timestamps record receipt rather than an invented physical-action date. Interactive browser/assistive-technology verification remains pending.

After shown is acknowledged, plain actions are available: open memory/source, useful, keep, show less, and continue. Open remains a nonterminal explicit action; useful/keep/show less/continue resolve the stop. A source opens only after its event is acknowledged and does not imply contact. Failed requests retain event UUID/payload for retry and never remove a stop as successfully resolved. Conflict refresh reconciles other tabs. Monotonic response merging prevents delayed acknowledgements from restoring resolved stops or undoing completion.

POST accepts strict start/event envelopes, derives owner identity from private server configuration after owner-session authorization, enforces exact HTTPS Origin through the shared dashboard guard, bounds actual streamed body bytes at 16,384, rejects malformed UTF-8/unknown fields and returns private no-store responses. GET requires owner read authorization and performs no database mutation. Old artifact/action envelopes are rejected. `/api/walk/hello` is authenticated then returns 410; it no longer reads legacy synthesis or calls a provider.

The old due-date selector, runtime interval-action adapter, draft generator and old WalkCard have been removed. The legacy schedule store is retained only for synthetic compatibility validation; no live module imports it. Historical schedule rows remain preserved for export. The live Walk has no overdue mark, backlog count, SM-2 mutation, or automatic contact update.

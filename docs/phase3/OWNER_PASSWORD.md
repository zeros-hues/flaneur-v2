After matching valid input, the tool adds `OWNER_PRINCIPAL_ID` and `OWNER_PASSWORD_HASH` to the repository `.env`. It retains an existing valid owner UUID, refuses an already configured password, and changes only the owner settings. Existing unrelated values, standard newline style, and UTF-8 BOM are retained. Literal hash dollar signs are escaped for Next's variable expansion and verified with the actual installed environment loader. Only the salted hash is stored; plaintext is never written. The helper does not load configured secrets into process environment, contact a database, create sessions, or activate login.

An exclusive setup lock prevents simultaneous tool runs. The tool writes a private-mode temporary file beside `.env`, syncs it, checks for file edits/replacement, then renames it over the target. Temporary credential files and locks are cleaned up after handled failures; their names are ignored by Git. It refuses symlink/non-file targets. Avoid editing `.env` while setup runs; detected edits are preserved and abort setup, but this is not an interprocess transaction with unrelated editors. The filesystem's Windows ACLs still govern access to the private workspace. Rotation is intentionally refused because it requires coordinating session revocation.

The provider takes a server-supplied owner UUID and encoded password hash. It verifies the exact submitted credential and returns a write grant only for that configured owner. It does not trim or normalize the password, accept a client-supplied owner/permission, or fall back to `CAPTURE_SECRET`. The login handler supplies origin checks, a required deployed throttle, strict input limits, and private failure responses.

Hashing uses Node's asynchronous scrypt with a fixed versioned profile: N=32768, r=8, p=3, 64 MiB maxmem, a fresh 16-byte random salt, and a 32-byte derived key. This is one of [OWASP's listed scrypt profiles](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); the implementation follows the [Node crypto scrypt API](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback). The record format is `flaneur-scrypt-v1$<salt-base64url>$<key-base64url>`. Fixed parameters prevent stored configuration from requesting unbounded work; comparison uses equal-length `timingSafeEqual`. Malformed/unsupported/noncanonical records fail at provider construction with a stable error that contains no hash.

Trusted enrollment accepts at least 15 Unicode code points and at most 1,024 UTF-16 units, rejecting NUL and malformed Unicode. Login does not truncate credentials. The enrollment helper returns the hash to its trusted caller and performs no printing, filesystem writes, or environment loading. Actual enrollment/configuration needs a private local or deployment setup mechanism that keeps both password and hash out of chat, logs, command arguments, and version control. Password rotation and session revocation must be coordinated explicitly; changing the provider hash alone does not revoke previously issued sessions.

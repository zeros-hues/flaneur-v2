The old export implementation has been removed. See [v2 export contract](../export/MEMORY_EXPORT_V2.md). Earlier descriptions below of the legacy export payload reflect the dashboard-auth stage.

Implemented locally 2026-10-12 after the user confirmed password setup. The private Next-loaded readiness check now validates password configuration, HTTPS origin, and runtime database URL; no values are exposed. The configured origin is `https://flaneur-seven.vercel.app`. No Vercel environment or deployment was changed.

`/login` now submits the exact owner password as JSON to `POST /api/session`. It preserves whitespace, never stores the password in React state/storage/URLs, clears the field after an attempt, and shows generic mismatch/throttle/unavailable feedback. The Node-only session route uses the prepared private scrypt provider, PostgreSQL throttle and revocable session stores. Successful login issues the Secure/HttpOnly/Strict host cookie and returns no token in JSON. Settings offers this-device and all-device sign-out; revocation errors retain the cookie and show failure rather than claim success.

The server-only runtime composition uses the existing `DATABASE_URL` pool. It never uses `DIRECT_URL`, which remains for administration. Configuration is initialized lazily and failures are private/fail closed. Restart the server after changing owner credentials or origin. Normal login/logout operations write the auth tables; this implementation turn did not submit a password, create a real session, consume a real owner throttle allowance, or perform database mutations.

Every existing protected dashboard page now validates the owner session using the database on access. Missing/invalid/expired/revoked sessions redirect to login; store failures throw a constant private error. Dashboard APIs await the shared guard before body handling or notebook work. GET/HEAD require read permission; other methods require write and an exact configured Origin. Explicit foreign Origin and cross-site/same-site fetch metadata are rejected. Browser POSTs use the browser's Origin, not a synthetic host header. Requests carrying only the old capture-secret cookie/header cannot access dashboard routes.

`/api/capture` retains its separate extension header credential and implementation. Other health/static endpoints retain their existing behavior. This authentication slice does not activate capture v2, review v2, export v2, backfill, workers, or provider migrations. The existing export payload remains legacy even though its route now requires owner sessions. Existing stored legacy cookies are ignored for dashboard access, without needing to print or send their secret back to the client.

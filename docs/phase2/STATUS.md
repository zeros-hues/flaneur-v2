## Prepared locally

- Strict version-2 capture envelope with a per-save UUID, adapter/kind, original source/HTML, optional explicit reason, extension version, and client capture time. The envelope is source-neutral; only the LinkedIn profile/post adapter is accepted initially.
- Payload fingerprints distinguish a transport retry from a changed request. Request reuse with different HTML, reason, URL, or other envelope fields yields a conflict. New intentional saves retain separate encounters.
- Injectable save service and PostgreSQL store designed to commit raw compressed snapshot, encounter, User reason observation, processing head/job, and request receipt atomically before acknowledging saved. Parsing and enrichment are absent from this save transaction.
- Prepared authenticated handler with bounded streaming JSON, validation, and sanitized 400/401/409/413/503 responses. Authentication precedes private body reads. A replay reports the stored request's actual processing state rather than falsely claiming it is still queued.
- Persistent outbox abstractions, trusted-context Chrome storage, serialized session operations, backoff, explicit resume after an authentication block, and validation of durable acknowledgments. A retry retains its UUID and payload across reloads. Storage failure does not report queued, and malformed/legacy acknowledgments never remove a queued capture.
- Durable processing schemas and injectable queue/worker stores: leased jobs, bounded attempts, per-scope input heads, run history, lease renewal, current-token/input checks, superseding obsolete work, and transactional output application. Database clock checks prevent a lease expiring during output application from committing that output.
- Migration 0011 prepares snapshot metadata, request/job/run/head tables, cross-record capture guards, and immutable originals/request receipts. Legacy parser projection/coverage updates remain possible; raw captured bytes, URLs, capture time, and established metadata cannot be rewritten.

The server store never creates a pool or loads credentials. It is not a runnable migration/capture command. The extension transport has no global endpoint/secret access and is not enabled in the packaged runtime.

## Limits and provenance

The prepared handler accepts at most 20,100,000 raw JSON bytes, 10,000,000 UTF-8 HTML bytes, 8,000 source-URL characters, and 5,000 reason characters. These are implementation bounds, not measured hosting capacity. Confirm platform request limits before activation and align capture/storage bounds accordingly. Chrome storage quota can reject queued payloads; never discard another saved payload to make room or falsely confirm local persistence.

Client capture time is retained with `client_clock_unverified`; server receipt time is separate. A supplied reason is User, not inferred. Missing reasons are not fabricated by this foundation. Post URNs can provide the snapshot's canonical post URL; the original submitted URL remains in the request/context.

Phase 3 has replaced the initial `parse-v2-contract-1` fingerprint in the disabled capture store with shared field-extractor/text-normalizer and identity-proof versioning, and prepared bounded extraction, exact field evidence, a parse-only job factory, fenced output application, explicit identity confirmation, and current-input retrieval filtering. See [Phase 3 status](../phase3/STATUS.md). No worker ran. Prompt/model/input changes must invalidate dependent derivations through the scope head. Broader resolution, complete review/downstream invalidation, and real SQL/DOM validation still require integration; having a queue is not evidence that the current parser/merge implementation meets v2 requirements.
